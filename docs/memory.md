# 跨对话记忆：方案

同一段对话里，前面聊过的话已经在。每一轮浏览器都把这段的全部消息再发给模型，所以问「我上一句说了什么」它看得到。换一段新对话时，请求里只有新的这几句，模型看不到 `chats.json` 里的其它记录。要补的是这一层：新对话记得以前各段聊过什么。

这和连网一样，不改权重。ChatGPT 的记忆也是放在提示词里的文字，加上一个可检索的旧对话库，不是把聊天写进模型。

## 现在各家怎么做

两层，都要。只做其中一层会漏掉一类问题。

| | 每段新对话里始终带着 | 按需才去翻 |
|---|---|---|
| ChatGPT | 一小段「你让我记住的事实」（名字、偏好、在做的事）。设置里能看见、能删 | 稍后加的「参考历史聊天」：模型搜索旧对话，不把全部历史塞进窗口 |
| 本机这一版要对齐的 | 置顶事实，加上最近几段对话的日期和一句话摘要 | 工具 `recall`，从 `chats.json` 里摘出相关原句 |

32k 窗口装不下全部历史。几十段对话全文每轮都 prefill，第一句会变慢，而且无关的旧话会挤掉当前问题。所以全文留在文件里，提示词里只放摘要和命中的摘录。

## 一轮里发生什么

```text
新对话的第一句
    |
    |-- 系统消息：置顶事实 + 最近对话的一行摘要
    |-- 用户的问题
    v
模型直接回答，或调用 recall("上次说的学习率")
    |
    |-- 在本机 chats.json 里按词查找，返回日期、标题、原句
    v
模型根据摘录回答，并说明是哪一段
```

`recall` 走 [web-search.md](web-search.md) 里同一个服务端工具循环，和 `web_search` 共用次数上限。不带服务端标志的请求（Claude Code）不自动翻聊天记录。

查找先做关键词，扫已有的 JSON 即可。一个用户的对话规模用不上向量库。以后摘录对不上了，再加嵌入。

## 记在哪

两份文件，都在本机，不进仓库。

| 文件 | 内容 | 谁来写 |
|---|---|---|
| `~/.local/share/tokenrush/chats.json` | 每段对话的全文。已经有了 | 每轮结束，和现在一样 |
| `~/.local/share/tokenrush/memory.json` | 置顶事实；每段对话一条 `{id, 日期, 标题, 一句话}` | 见下面 |

一句话摘要在该段对话一轮结束之后生成：用同一次驻留的模型，另开一次很短的生成，输入是这段的近期消息，输出限制在一两句。摘要写进 `memory.json`，不写进那段对话的 `messages`，避免下一轮把摘要又当成用户说过的话。

置顶事实只有两条路可以进文件，避免模型每轮都改记忆：

- 用户在页面上自己写、改、删。
- 模型调用 `remember(text)`。页面上显示刚记下的那条，用户能删。

`remember` 的文本原样保存，不再摘要。删掉一条就从以后的系统消息里消失。

## 每段新对话带上的系统消息

固定预算，大约 1500 token，超了就丢掉更老的摘要、留下置顶事实。内容是：

```text
你记得这些事实：
- …

最近的对话：
- 2026-10-09 《投机解码》 用三句话解释了草稿模型和验证
- 2026-10-08 《GSM8K》 跑了测试集前 200 题
需要某段的原话时调用 recall。
```

这段系统消息由服务在网页请求上拼好，不要求浏览器每次自己附带。它算在提示词里，当前对话变长时和普通消息一样占窗口。页面上已有的八成窗口提示同样适用。

当前这段对话自己的全文仍然整段重发。窗口装不下时，服务继续返回 400，由用户新开一段。新开的那段靠摘要和 `recall` 接上旧内容。不在这里做「悄悄删掉当前对话的前半」。

## 还缺的

1. `memory.json` 和上面的系统消息拼接。最近摘要可以先只用现成的标题（第一句用户话），摘要生成可以后补。
2. 工具 `recall(query)`：在其它对话的正文里找包含这些词的片段，返回最多几条，每条带日期和标题。不返回当前这段，避免把刚刚说过的话再贴一遍。
3. 工具 `remember(text)`，以及页面上的事实列表（增删）。
4. 一段对话结束后的一句话摘要。和搜索共用同一次模型加载，不另起进程。

`chats.py` 仍拒绝 `tool` 角色。`recall` 的结果要留在这段对话里，跟进时才不用再搜一遍，所以消息角色的放宽和 [web-search.md](web-search.md) 是同一处改动。

## 怎么算做完

不占 GPU。准备两段写好的旧对话，新请求的系统消息里能看到它们的标题。桩模型调用 `recall`，假执行返回其中一句原话，第二轮回答带上这句。删掉一条置顶事实之后，下一次系统消息里没有它。不带服务端标志的请求不读取 `memory.json`。
